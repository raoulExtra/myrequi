# R4.1: File-level evidence for R4

The demo project SHALL provide file-level evidence for R4
that can be verified with a reusable Python check.

## R4.1 checks
- R4.1.1: A Markdown evidence file SHALL exist at
  `prj/base/docs/memory-and-filesystem-guidance.md`.
- R4.1.2: The evidence file SHALL mention `continuity.db`.
- R4.1.3: The evidence file SHALL describe what belongs in
  the filesystem by listing or naming filesystem-resident
  project material.
- R4.1.4: The evidence file SHALL mention `starter.md` as
  the memory-db guidance reference.
- R4.1.5: The R4 requirement file SHALL contain
  term[REF_EXISTS] references for the evidence values.
- R4.1.6: The reusable Python checker SHALL support these
  arguments:
  - R4.1.6.1: `--root` SHALL set the base folder for
    relative paths.
  - R4.1.6.2: `--path` SHALL set the current relative folder
    for following file arguments until changed again.
  - R4.1.6.3: `--requi` SHALL select the requirement file
    relative to the current folder.
  - R4.1.6.4: `--evidence` SHALL select the evidence file
    relative to the current folder.
  - R4.1.6.5: `--filesystem-cue` SHALL add a
    filesystem-content cue to check in the evidence file.
  - R4.1.6.6: `--marker` SHALL set the marker name used
    inside `[]` to extract required values from the
    requirement file.
  - R4.1.6.7: A marker line SHALL place the marker directly
    after the term, as in `term[MARKER]`, and the checker
    SHALL extract the term before the marker.
  - R4.1.6.8: `--link-target` SHALL add a target text string
    to check in linked files.
  - R4.1.6.9: `--link-file` SHALL select a link file
    relative to the current folder.
  - R4.1.6.10: `--json` SHALL enable JSON output.
  - R4.1.6.11: `--json-in` SHALL load a JSON array of
    arguments into the current command sequence.
  - R4.1.6.12: `-v` / `--version` SHALL show the checker
    version.
