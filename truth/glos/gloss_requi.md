# Glossary

| Term | Compact definition |
|---|---|
| Stakeholder | Person/group with an interest in the outcome |
| Actor | Person/system interacting with the system |
| Goal | Outcome an Actor or Stakeholder wants |
| User Story | Short statement of a user's desired capability and value |
| Use Case | Interaction between Actor and System to achieve a Goal |
| Scenario | One specific path through a Use Case |
| Happy Path | Expected successful Scenario |
| Alternative Flow | Valid deviation from the Happy Path |
| Exception Flow | Path caused by an error or failure |
| Requirement (REQ) | Testable statement of what must be true |
| Functional Requirement (FR) | Required system behavior |
| NFR | Required quality, performance, security, etc. |
| Acceptance Criterion (AC) | Testable condition for accepting behavior |
| Constraint | Boundary the solution must obey |
| Assumption | Something currently treated as true |
| Dependency | Something required from elsewhere |

The relationship is more important than memorizing the definitions:

Stakeholder → Goal → User Story → Use Case → Scenarios → Requirements → Acceptance Criteria
